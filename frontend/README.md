## 🌟 Key Features

### 1. Real-Time 5-Second Polling Engine
- Background heartbeat polls the Go backend every **5,000 milliseconds**.
- An animated countdown pill badge in the header displays live progression: `Poll: 5s` → `Poll: 1s`.
- Controls to **Pause** or **Resume** auto-polling at will.
- Manual **"Refresh Now"** button with a spinning sync animation.

---

### 2. Adaptive Light & Dark Mode
- Seamless toggle in the top header between a clean, high-contrast **Light Mode** and sleek **Dark Mode**.
- Smooth transitions across metric cards, navigation panels, data tables, modals, and Chart.js tooltips.
- Stores user preference in `localStorage` (`iot_theme`) so the mode is maintained across browser reloads.

---

### 3. Left Sidebar Navigation Cards
The left sidebar provides instant access to the core platform layers:
- **📊 Live Dashboard**: Primary monitoring cockpit with real-time temperature/humidity cards, trend charts, and raw packet log.
- **🏢 Tenants & Workspaces**: Create, edit, and switch between isolated multi-tenant environments.
- **📡 Groups & Channels**: Configure logical telemetry channels and MQTT routing hierarchies (e.g. `devices/+/telemetry`).
- **📟 Clients & Edge Devices**: Central device registry with real-time `online`/`offline` indicators, device ID copying, and deletion controls.
- **🔑 Key & Config Generator**: Built-in credential studio to provision edge microcontrollers.

---

### 4. Cryptographic Key & Firmware Config Generator
Generates production-grade credentials for your ESP32 microcontrollers:
- **Tenant ID**: Standard RFC 4122 UUID.
- **Channel ID**: Unique channel slug (e.g. `chan-dht22-alpha`).
- **Secret Key**: High-entropy cryptographic token (e.g. `iot_sec_a8f921d...`).
- **One-Click C++ `config.h` Generator**: Generates an exact C++ header with WiFi, MQTT broker, and device credentials that can be copied directly into PlatformIO or Arduino IDE!

```cpp
// Generated by IoT Management Portal
#pragma once

#define WIFI_SSID       "Your_WiFi_SSID"
#define WIFI_PASSWORD   "Your_WiFi_Password"
#define MQTT_BROKER     "192.168.1.100" // Your PC/Server IP
#define MQTT_PORT       1883

#define TENANT_ID       "a0000000-0000-0000-0000-000000000001"
#define CHANNEL_ID      "chan-dht22-alpha"
#define DEVICE_ID       "esp32-node-01"
#define SECRET_KEY      "iot_sec_9f81a7d2b4e803c6152a4e99"
```

---

### 5. Clean Workspace Lifecycle & Device Management
- **Zero Mock Devices**: The dashboard starts clean with zero hardcoded fake nodes.
- **Inviting Empty State**: If a workspace has no connected hardware, a clear onboarding card guides the user to provision an ESP32.
- **Single-Click Device Deletion**: Each device card has a trash icon to remove it and its telemetry from both memory and the backend.
- **"Clear Test Devices" Action**: A single button to wipe all test devices from a workspace and reset the view.

---

### 6. Live Telemetry Metric Cards
- **Temperature Card**: Real-time reading with instant **°C / °F unit toggle**, window min/max values, and delta indicators.
- **Relative Humidity Card**: Humidity percentage (% RH), window min/max bounds, and comfort level rating.
- **Signal & Node Health Card**: ESP32 WiFi RSSI signal strength (dBm) with visual reception bars, uptime counter, and telemetry sequence number.

---

### 7. Interactive Dual Y-Axis Historical Chart
- Powered by **Chart.js** with smooth cubic spline curves and gradient area fills.
- **Dual Y-Axes**: Left axis scales for Temperature (°C/°F) and right axis scales for Humidity (% RH).
- **Time Window Filters**: Switch history view between Last 20, 50, or 100 telemetry data points.
- **Legend Series Toggles**: Hide or show individual metrics dynamically.

---

### 8. One-Click Test Packet Injector
A built-in **"Send Test Packet"** button located at the bottom of the dashboard sends synthetic DHT22 sensor readings directly via `POST /api/v1/devices/{id}/telemetry`. This allows instant end-to-end verification of the UI and polling engine even when physical ESP32 boards are not connected.

## ⚡ Getting Started

### 1. Install Dependencies
```bash
cd frontend
npm install
```

### 2. Start the Development Server
```bash
npm run dev
```
Open **`http://localhost:3000`** in your browser.

### 3. Build for Production
```bash
npm run build
npm run preview
```
The optimized bundle is written to `dist/`.

## ⚙️ Configuration & API Proxy

By default, the Vite dev server (`vite.config.js`) proxies API requests to the Go backend on `localhost:8080`:
```javascript
server: {
  port: 3000,
  proxy: {
    '/api': 'http://localhost:8080',
    '/health': 'http://localhost:8080',
  },
}
```

If your backend is hosted on a remote server or different port, create a `.env` file in `frontend/`:
```env
VITE_API_URL=http://192.168.1.100:8080
```
